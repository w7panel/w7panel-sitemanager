# 站点管理：界面优化与新增功能方案

需求来源：[TAPD 1016289](https://www.tapd.cn/tapd_fe/62789787/story/detail/1162789787001016289)。本次完成界面调整，并将面板原有文件管理、终端命令和运行日志内置到站点 tab。本次也已实现自定义域名编辑和独立重启应用；主域名名称继续保持不可编辑、不可移除。

网关开关延续已有流程：开启后读取配置，显示“待应用”，点击“保存配置并开启”才会校验并切换流量；读取或校验失败展示原因。关闭已生效网关仍需确认，失败时保留服务端确认的状态。PHP-FPM 的关闭限制不变。

`scripts/site-menu.mjs` 只根据输入的 MicroApp JSON 生成带 `resourceVersion` 检查的 JSON Patch：移除外层文件管理快捷入口，将其自定义子菜单归到站点配置，保留其他菜单及绑定信息。发布时需将生成的补丁应用到站点工具的 MicroApp；本次没有修改在线资源。旧文件路径仍保留，并进入内置文件 tab。

## 已实现：自定义域名编辑与应用重启

### 自定义域名编辑

自定义域名行提供“编辑”，进入行内输入后可保存、取消。主域名名称保持只读，不显示编辑入口，移除始终禁用；方法和保存逻辑再次检查主域名，不能通过自定义域名编辑将其替换为主域名。现有主域名的自动 HTTPS 开关保持原有行为。

编辑只开放给当前站点的单域名、单根路径、自动证书或无证书的 Ingress；复杂路由、手工或共享证书形态请在面板域名管理处理。保存时使用现有 Kubernetes、DNS 配置和容器 exec 接口编排，无需新增后端接口：

1. 重新读取站点上下文和原 Ingress，核对 UID、`resourceVersion`；校验域名格式、白名单和同命名空间内重复域名。
2. 保留原有转发规则、入口类型、自定义注解及自动 HTTPS 状态。自动证书的 TLS hosts 更新为新域名，使用新的 Secret 名称，避免改动旧证书共享的内容；泛域名重新匹配已验证 DNS 配置并获取绑定新 host 的签发授权，旧授权不继承到新 host。
3. 网关开启时，先加入新 `server_name` 并校验、reload，再提交 Ingress。网关文件写入前比较读取的原内容；补偿时同样比较，避免覆盖其间修改的配置。
4. 请求失败会回读 Ingress，区分未提交、已提交但响应丢失、无法确认。未提交时尝试恢复预备的网关修改；无法确认时保留草稿、禁用重复保存，提供“检查提交结果”。
5. 成功后仅在没有其他 Ingress 引用旧域名时清理旧网关别名。清理失败明确提示新域名已保存及待检查项。提示用户修改 DNS 解析，自动证书需等待签发。

编辑草稿参与现有离开确认，运行配置保存失败和独立重启均保留草稿。跨 Ingress、证书和 Nginx 的操作依赖现有接口顺序与补偿，不提供跨资源事务；发布前仍需真实集群联调。

### 独立重启应用

启动命令区域提供“重启应用”。确认框说明访问可能短暂中断；存在未保存版本、启动命令、端口或域名时，明确按已保存配置重启，并保留页面草稿。取消确认可继续编辑。

重新读取主 Deployment，核对 UID 和 `resourceVersion`，通过带前置检查的 JSON Patch 只更新 Pod template 的重启时间和本次操作标记；多容器、镜像、命令、端口、网关和系统盘清理流程均保持原有配置。已停止或暂停的应用禁用重启并说明原因。

提交后按本次 generation 和操作标记检查控制器观察进度、更新副本数、就绪及可用副本数；忽略旧 generation 的就绪数据。应用启动失败、15 分钟超时或网络异常时展示原因与运行日志入口。提交状态不明或等待中断时保留操作标记，提供“检查重启状态”，禁止盲目重复提交。确认 rollout 失败后允许用户明确重新发起；资源被重建或配置被其他操作改动时保留草稿并要求刷新。重启确认、执行与运行配置保存互斥。

## 已实现：复用面板的三个内置 tab

内侧菜单顺序为：基础配置、网关配置（具备能力时）、文件管理、终端命令、运行日志。三个工具 tab 不再跳出站点配置或打开弹窗。

站点工具通过宿主提供的 `getSitePanelUrl(view)` 获取绑定当前站点、命名空间的嵌入入口。面板新增 `/dialog/appgroup/:group/site-panel/:view`，在独立 frame 中加载原有组件与样式；会话通过 fragment 传递，继续使用面板原有 API 权限检查，不出现在 HTTP URL 或 Referer 中。Wujie 初始化只传递延迟构造函数，不增加 AppGroup 初始化请求。

2026-11-16：站点工具在创建 iframe 前检查宿主返回地址的 fragment 中是否包含非空 `paneltoken`；缺失、空串或纯空白时显示登录凭据缺失提示，不创建 iframe。重试会重新获取宿主地址，切换时凭据缺失会清空旧 frame 地址。此处只阻止无凭据页面进入面板的默认登录态回退，不代替服务端权限校验或过期会话处理，也不更改主、子集群原有认证方式。新增空凭据与恢复重试回归，全量 96 项测试及生产构建通过。

- 文件管理直接使用面板 `files.vue` 的组件模式，沿用站点目录解析、文件浏览、上传、编辑与权限操作。`componentData.namespace` 明确指定当前命名空间。离开文件 tab 前委托原生编辑器检查未保存修改，取消时保留原页面。
- 终端直接使用 `web-shell.vue`，提供主应用 Pod、正在运行的容器、`/bin/sh` 或 `/bin/bash` 选择器；使用原有连接、重连与尺寸适配逻辑。
- 日志直接使用 `pod-log.vue` 的 `inline` 模式，保留跟随、容器和日志条数选择；由外层选择主应用 Pod，保留已退出实例供排障。
- Pod 按主应用 Deployment 的完整 selector 查询，不按名称前缀猜测，也不选择网关工作负载。终端过滤无运行容器和正在终止的 Pod，日志保留退出实例。
- 切换 tab 卸载对应 frame，浏览器释放终端连接与日志请求。旧面板缺少嵌入入口时显示升级提示。

需要同时发布站点工具和相邻 `w7panel-ui` 的配套修改。现有文件菜单迁移补丁仍只生成 JSON Patch，本次没有修改在线资源。
